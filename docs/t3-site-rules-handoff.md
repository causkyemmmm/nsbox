## 4. 每站必填模板

每个站点一份文档，严格使用以下结构。缺项视为未交付。

### 4.1 配置项

| 字段 | 内容 |
|---|---|
| 站点 `key` | 配置中的唯一标识 |
| 站点 `name` | 显示名 |
| `type` | 预期为 3 |
| `api` | **从配置中实际取值**；若配置未给出，记录发现方式 |
| `ext` | 完整内容（脱敏）。逐字段解释用途 |
| `ext.siteUrl` | 立播等站点从此处读取站点地址，记录实际内容 |
| `header` / `UA` | 配置声明的标头，与实际请求是否一致 |
| `searchable` / `quickSearch` / `filterable` | 配置值 |

> **配置未提供站点地址时**：必须记录发现方式（另一配置项 / 重定向 /
> 硬编码 / 接口返回），以及发现失败时该站应如何标记。

### 4.2 请求样例

每类接口各一个，**必须脱敏**：

- 分类（categories）
- 列表（vod list，含分页参数）
- 搜索
- 详情（含选集）
- 播放解析

每条记录：

| 字段 | 内容 |
|---|---|
| 方法与完整 URL | 含 query 参数顺序 |
| 请求头 | **完整列出**，标注哪些是必需 |
| 请求体 | 如有 POST，记录格式 |
| 实际响应 | 脱敏后的原始 JSON 片段 |
| 响应编码 | UTF-8 / GBK / 其他 |

### 4.3 数据格式映射

| TVBox 概念 | 该站实际字段 | 差异说明 |

| `vod_play_from`（多线路 `$$$`） | | |
| `vod_play_url`（`#` 拆集、`$` 拆集名与ID） | | |

填写：

### 4.5 播放解析

| 字段 | 内容 |
|---|---|
| `resolvePlayback()` 入参 | `flag`（线路名）与 `episodeId` 的确切来源 |
| 是否能解析出媒体直链 | 是 / 否 |
| 必需请求头 | 完整列出。**缺哪个会导致什么失败** |
| 是否需要 Cookie / Token | |
| 是否需要浏览器解析 | 是 → T2 置 `NeedsBrowserEngine`，**不得返回网页URL** |

## 5. 夸克专项（T9 依赖）

夸克比其他三站多两个必填项，**T9 不能在拿到这些之前开工**：

### 5.1 免登录路径验证

- 是否存在免登录即可获取播放 URL 的路径
- 实测请求 + 响应样例
- 有效期与失效表现
- 结论必须基于**实测**，不是文档推测

### 5.2 扫码登录流程

若确需登录，记录完整流程：

| 字段 | 内容 |
|---|---|
| 二维码接口 | URL + 参数 + 响应 |
| 轮询接口 | URL + 间隔 + 终止条件 |
| Token 存储位置 | 建议路径与格式 |
| Token 有效期 | 实测 |
| 失效表现 | 实测 |
| 重登触发点 | |

**日志脱敏要求**：T9 实现时，Cookie / Token / 分享凭据**一律不得进入
日志**。T3 需在文档中明确列出哪些字段属于必须遮盖的敏感字段。

## 6. 许可证核查

对每份**实际引用或复制**的代码：

| 来源 | 引用位置 | 许可证 | 是否可复制进MIT 项目 |
|---|---|---|---|

判定规则：

- 仅**阅读并理解行为**后自行用 C++ 重写 → 标注"参考实现思路，独立编写"
- **直接复制代码或片段** → 必须标注许可证并确认兼容性
- 不确定 → 明确写"许可证不明，需人工确认"

**不得默认宽松。** 这是硬性要求。

## 7. 无法验证时的处理（重要）

工作单明令：**「找不到公开 `Guard` 实现时，明确记录可验证的站点接口及
缺口，不将推测写成已支持。」**

因此每份文档末尾**必须**有：

```markdown
## 未验证项与缺口

- 未验证内容：
- 原因：
- 阻塞哪个任务的哪些接口：
- 建议如何处理（标记为暂不支持 / 继续调查）：
```

**禁止**把推测写成结论。若某接口没抓到真实样例，就写明"未验证"。

## 8. 阻塞处理

某站点规则失效时：

1. T3 交付**可复现的请求、响应及失败原因**
2. T4 将该站标为**暂不支持**
3. **不得**以假直链或静默回退冒充完成
